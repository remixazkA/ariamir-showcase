# Hardware Benchmark and Compatibility

## Purpose

Track how Ariamir workloads behave across real components and workstation configurations.

## Report template

Each public hardware report should record:

| Field | Value |
| --- | --- |
| Component | |
| Model / revision | |
| Firmware / driver | |
| Host CPU | |
| Host GPU / accelerator | |
| System RAM | |
| Workload | |
| Backend / model | |
| Run count | |
| Throughput / latency | |
| Peak VRAM / RAM | |
| Thermal / power notes | |
| Compatibility result | |
| Known issues | |

## Interpretation

Hardware reports should distinguish raw performance from engineering suitability. A component can be technically compatible yet poorly matched to a workload, or provide value in a specialised stage without accelerating the entire AI pipeline.
